# 一字溯源：计份口径 v2

基础原则来自 `skills/analyze-bazi-fene.md`。本版依据用户对「庚辰、丁亥、己卯、乙丑」的反馈修正 v1：总数相同不代表来源正确；必须同时验证每份的组成。下面区分用户明确规则与产品补充口径，便于继续修订。

## 用户明确的规则

1. 丁火在此例为两份：月柱天干丁自身一份；家内时干乙与日支卯生扶合看为一份。不能解释成丁自身加亥中藏甲。
2. 不因地支藏干中出现生我五行便立根或计份。根看长生、同五行根、墓库等明确关系。
3. 丁火的根明确为寅、巳、午、未、戌：寅为长生；巳午为同五行根，可再标识禄；未戌按此口径认墓库根。亥藏甲不能视为丁根，卯木生丁也属于生扶，不能改称丁根。
4. 同一柱最多合计一次。目标自身与坐下根合成一份，不再拆天干、地支或藏干。该合并同样适用于岁运柱。
5. 家内有实际联系的生扶合看：本例日卯与时乙是同一条家内生扶链，不因隔着日干便排除时乙，也不能把乙、卯各拆一份。
6. 同五行天干不是根，不计为来源份额；无论同干、异阴阳、家内家外或岁运，均只展示同气关系，也不经同气天干展开根源或触发家内合并。它所在柱的地支若是目标的根，仍按地支根独立计入。天干生我者继续按生扶条件计份，目标自身仍保留自身的一份。

## 查根与补充表

根使用显式对应表 `ROOT_RELATIONS`，藏干仅补充本中余气说明，不作为「有生我藏干即有根」的快捷判据。

| 目标五行 | 对应根 | 口径来源 |
| --- | --- | --- |
| 火 | 寅、巳、午、未、戌 | 丁火依用户明确举例；丙火沿用同五行对应表 |
| 木 | 亥、寅、卯、辰、未 | 产品补充：长生、同五行根、墓库及库中余气根 |
| 金 | 巳、申、酉、丑、戌 | 产品补充，同上 |
| 水 | 申、亥、子、辰、丑 | 产品补充，同上 |
| 土 | 寅、巳、午、辰、未、戌、丑 | 产品补充：土寄火与同五行根；不因申藏戊自动认土根 |

非火行表属于可调整的产品默认值，不声称是用户已经逐项确认的规则。长生采用五行口径，不改用阴干逆行十二长生来覆盖用户给定的丁火寅根。库根关系、能否开库和能否取得分别判断。

## 生扶、展开与合并

- 目标自身先记一个来源单位。无根时它只是虚浮落点，不等于有效力量。
- 直接根逐项列位置与依据；同柱天干、根支、藏气、禄的多条路径全部归到同一个柱单位中。多个无生扶连接的家内直接根仍保留各自来源，不简单按参与方数量封顶。
- 地支生扶先看本气五行及位置。仅杂气藏干相生只列「藏干相生 · 不计份」，既不立根，也不作为独立生扶份额。同柱本气生扶也并入该柱，不额外拆份。
- 对天干目标，相邻原局天干、家内供方和当前岁运供方中的生我者可参与。明透供方须有明确根基；家内按日时整体检查联系，不限于相邻天干。因此月丁可以接受家内时乙与日卯的生扶。同五行天干不进入这条计份与展开流程。
- 对地支本气或藏干目标，保持同柱明透供方的判断，不生成地支内部自生循环。
- 供方的同柱根或家内相连根可以展开到目标，家内这条生扶链最终合记一份，所有具体路径保留。供方的其他外部根只作为其有根的依据，不自动把全盘根份数传递至目标，也不无限递归寻找生扶者。
- 若本命自身落点已在参与的家内生扶链中，同样按同柱合并后再合并家内链，不能把自身重复列出。
- 参与方账本同步包含已经计份的生扶来源，不再只记录自身和直接根。日时列家内，年、月分别列家外；岁运单列。

最终份额是这些实际来源单位合并后的数量。它不是等量强度、股权、人数、金额或所得，也不能将多个目标的份数直接相加为全盘力量。

## 反馈命例的期望结果

四柱：庚辰、丁亥、己卯、乙丑；目标：月干丁。

| 份额 | 组成 | 路径与依据 |
| --- | --- | --- |
| 1 | 月柱天干丁 | 自身落点；亥藏甲只列线索，不另计 |
| 1 | 家内生扶（时柱乙、日柱卯） | 日卯木生丁；日卯为时乙之根，乙生丁；日时家内这条链合看 |

合计 2 份，原局丁无根、有生扶。不能在第二份中显示「月柱地支亥」。若将丁坐下改成寅、巳、午、未或戌，坐下根与丁仍合为一份，家内乙卯另合一份。

## 岁运与展示

- 直接使用当前显示的本命、大运、流年、流月、流日，在浏览器中同步计算，无 AI、API、保存或扣点动作。
- 本命账本与当前账本分别计算，增量按实际参与的柱成员比较，避免合并单位换了名称就被误标为新增。
- 六冲、六合只标记目标或直接根位置的作用条件，不武断扣根、开库或合化。刑害破及成化等尚未折算。
- 地支概览按本气天干查十神与来源，其他藏干分别查看，不把一个地支归成唯一十神。
- 藏干单元格顶部对齐，保持固定的从上到下排列；各柱不会因藏干个数不同而上下居中。
- 缺失四柱、无效选择不输出结果；切换岁运清除旧下级时层，已消失的目标关闭详情。

## 回归验证

运行 `npm run test:bazi-sources`。除原有十神、藏干、岁运分层和无效输入外，必须核对反馈命例的「两份具体组成」、五种坐下根同柱合并、家内乙卯合并、删除供方后的变化、家外根独立参与，以及岁运切换后恢复原局来源。
