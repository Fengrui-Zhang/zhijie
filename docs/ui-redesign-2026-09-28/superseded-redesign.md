## 结论

建议保留智解现有的米白、墨色、金色气质，全面整理页面层级、操作位置和状态反馈。useLayouts 主要用于导航、列表、菜单、输入、切换和保存反馈；Libraries.dev 继续承担真实 AI 工作状态的视觉反馈。

本轮对 useLayouts 当前 **64 个注册组件**逐项匹配：**11 项核心采用并适配，9 项条件采用或仅借鉴模式，44 项本轮不采用**。这是组件选择方案，尚未将第三方代码加入应用运行。

## 三、视觉与交互规范

### 视觉方向：温润、清楚、适合长时间阅读

- 延续米白背景 `#f5f3ef`、墨色正文 `#211f1c`、棕金强调 `#9a661e`；状态绿/红保留文字辅助，避免只靠颜色。
- 主要内容用实色或接近实色底，降低多层模糊与阴影；玻璃只留给少量悬浮层。
- 页面标题桌面 26–30px、手机 22–24px；正文 15–16px，长分析行高约 1.75。专业密集标注按空间专项检查。
- 卡片圆角 18–24px；输入/按钮 12–16px；图表和命盘避免连续几层超大圆角。
- 主按钮使用墨色底和清晰浅色字；次按钮用描边或浅底；普通行操作弱化；危险操作带明确文字。
- 手机可交互目标至少 44px，表单输入保持 16px，保留浏览器缩放。
- 保留各系统既有意义颜色；“统一 UI”不等于把五行/星曜等业务颜色全部改为金色。

### 动效参数建议（实施时实机微调）

| 动作 | 建议 | 限制 |
|---|---|---|
| 按钮按压 | scale 0.98，100–140ms | 与全局 active 规则只保留一套 |
| Tabs 选中块 | 180–220ms 或阻尼较大的弹簧 | 所有中文标签始终可见，不挤压点击目标 |
| 菜单/提示 | opacity + y 4–6px，140–180ms | 不做反复弹跳，打开即能操作 |
| 抽屉/移动面板 | 220–300ms | 保持关闭按钮、Esc、焦点回归；拖动仅手柄区域 |
| 列表/卡片切换 | 200–260ms layout | 同一数据顺序，避免内容飞散和 Pack 隐藏 |
| 高级字段展开 | 180–220ms | 焦点/错误字段始终可见 |
| AI 工作状态 | 复用现有延迟显示逻辑与 ThinkingOrb | 单一区域负责主反馈；不模拟百分比或固定完成时间 |

全站同时支持 CSS `prefers-reduced-motion` 和 Motion 的减少动态效果配置。用户减少动态效果时，直接切状态或只保留短淡入。页面离开后停止持续动效。

### 全站统一状态契约

1. **idle**：动作与消耗额度可见。
2. **unavailable**：解释缺少什么条件，适当降低强调。
3. **loading-existing**：读取已有数据，使用轻量占位或“正在读取”。
4. **submitting / generating**：防重复提交；仍保持清晰文字；真实工具可提供阶段名称。
5. **success**：只有后端确认或实际复制成功才显示完成。
6. **error**：说明失败、保留输入/旧结果，给出有效重试；不把失败当完成。

## 四、实施方式

### A. 建立共用基础（先做）

抽取 `ActionButton`、`SegmentedControl`、`Menu`、`ResponsivePanel`、`Field`、`StatusMessage`、`EmptyState` 和统一动效配置。修复 disabled 对比度与中文输入法问题。用真实 `.app-shell`、Portal、窄屏检验。

当前项目为 Next.js 15 / React 19 / Tailwind 3.4；上游以 Tailwind 4 为目标。优先适配选中组件到现有项目；本次 UI 改版不捆绑全站 Tailwind 大版本升级。按实际裁剪代码确认是否需要新增 `motion`、`clsx`、`tailwind-merge`，复用已有图标，避免安装整个示例仓库的依赖。

### B. 框架、首页、命例库、记录

产出一组桌面/手机可审阅页面，再将相同组件扩展至两类命例与历史侧栏。主入口与搜索位置先定下来。

### C. 表单、命盘、运势、择日、专业功能

以公共表单/结果框架覆盖全部模型，保留各专业盘面语义。每类至少检查一个已有结果；没有合适已有数据时使用本地测试夹具，避免为了看 UI 创建真实 AI 消耗。

### D. 问智解与全部 AI 状态

只改当前实际使用的 `AgentChatWorkspace`；将加载、失败、工具调用、引用和结果操作统一。同步页面/弹窗里的重复分析面板。

### E. 设置、认证、账户与管理

统一所有边缘入口，补齐异常状态与无障碍。管理员写操作、账号删除等使用测试环境或模拟服务验收，生产只读检查。

### F. 联合验收与交付

检查以下矩阵后交付：

- 尺寸：360/390px 手机、768px 平板、1280/1440px 桌面；长中文、空数据、大量记录。
- 输入：中文输入法、触摸、键盘、手机横屏、软键盘与安全区。浏览器窄屏通过不等于真实 iPhone 通过，结果分开报告。
- 状态：读取、长请求（含超过 3 秒）、成功、失败、重试、无权限、额度不足、重复点击。
- 业务：历法转换/闰月/真太阳时、八字列布局、宫位选择、日期切换、历史重开、路由前进后退、复制/导出、计费不重复。
- 可访问性：Tab 顺序、焦点可见、对话框回焦、按钮命名、Tabs 键盘操作、`aria-live` 不重复播报、减少动态效果。
- 性能：对比改动前后的路由 JS 体积；列表快速滚动/频繁切换无明显掉帧；长期隐藏的面板不持续运行昂贵动画。
- 验证分层：类型/构建、关键业务回归、浏览器真实交互分别记录。构建使用不会顺带迁移数据库的入口。

实施时每批独立提交，关键业务回归通过后再进入下一批。最终是否部署按用户后续对实施的授权处理。
